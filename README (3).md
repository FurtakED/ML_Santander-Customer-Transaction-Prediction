# Santander Customer Transaction Prediction

Решение соревнования [Santander Customer Transaction Prediction](https://www.kaggle.com/c/santander-customer-transaction-prediction) (Kaggle).
Метрика — ROC-AUC.

## Результат

| | ROC-AUC |
|---|---|
| **Kaggle Public** | **0.92082** |
| **Kaggle Private** | **0.91912** |
| Локальная отложенная выборка (итоговый метод) | 0.9218 |
| Взвешенное усреднение: holdout / Public / Private | 0.9205 / 0.92002 / 0.91812 |

Итоговое решение — не ансамбль, а одиночная модель «по переменным»: 200 маленьких LightGBM, каждая на своей переменной
и её частоте, логиты складываются. Порядок моделей, выбранный по отложенной выборке, подтвердился на лидерборде
(«по переменным» выше усреднения и там, и там), расхождение holdout и Public — 0.001.

Username на Kaggle: Лена Фуртак. Скриншот результата: `submission_screenshot.png`.

## Задача

Бинарная классификация: предсказать, совершит ли клиент банка определённую транзакцию. Датасет анонимизирован —
200 числовых признаков (`var_0` … `var_199`) без описаний, 200 000 строк в train и столько же в test,
дисбаланс классов 89.95% / 10.05%.

## Схема валидации

На этом датасете легко получить честную на вид локальную оценку, которая не переносится на лидерборд, поэтому
валидация устроена так:

* **Отложенная выборка** (20%, стратифицированная) не участвует ни в отборе признаков, ни в подборе гиперпараметров,
  ни в подборе весов ансамбля — на ней только сравниваются финальные кандидаты.
* Все сравнения на train-части — `StratifiedKFold` **на одних и тех же фолдах**; разница меньше стандартного отклонения
  по фолдам не считается различием.
* Число деревьев не фиксируется: внутри каждого фолда 10% train-части отводится под раннюю остановку, а качество
  измеряется на валидационной части фолда, которую модель не видела.
* Частотные признаки считаются без таргета, поэтому их расчёт до разбиения не даёт утечки целевой переменной.
* Отдельно проверяется, не разошлись ли распределения train и теста после добавления признаков — adversarial
  validation (раздел 5). Отложенная выборка взята из train и такой сдвиг не видит в принципе.

## Ход работы

### 1. EDA

* Пропусков и дубликатов нет.
* Признаки практически не коррелируют друг с другом (|corr| < 0.01) и слабо — с таргетом (максимум 0.081).
  Линейных зависимостей нет, отбор признаков по корреляции бесполезен.
* Маргинальные распределения train и test совпадают: KS-статистика медиана 0.0034, максимум 0.0090 (`var_90`).
  Но это сравнение по одному признаку за раз — различия в комбинациях и частотах проверяются отдельно (раздел 5).

### 2. Настоящие и синтетические строки теста

Около половины строк `test.csv` синтетические — собраны из значений настоящих строк. Признак настоящей строки:
хотя бы одно её значение уникально в пределах теста. Факт обнаружен участниками соревнования (ноутбук
*List of Fake Samples and Public/Private LB split*, автор YaG320), идея взята оттуда.

Результат: ровно **100 000 настоящих и 100 000 синтетических** строк. Доля значений синтетических строк, найденных
среди настоящих, — 1.0000.

Это важно, потому что частотные признаки — главный источник качества в задаче. Если считать частоты по всему тесту,
синтетические копии завышают частоты значений настоящих строк:

| Способ подсчёта | Средняя частота в train | В настоящем тесте |
|---|---|---|
| по всему тесту (`cnt_all`) | 16.099 | 17.097 |
| только по настоящим строкам (`cnt`) | 12.326 | 12.325 |

### 3. Бейзлайны на сырых признаках

| Модель | CV ROC-AUC | std | holdout |
|---|---|---|---|
| Naive Bayes | 0.8882 | 0.0021 | 0.8882 |
| LightGBM | 0.8814 | 0.0029 | 0.8814 |
| CatBoost | 0.8752 | 0.0036 | 0.8747 |
| XGBoost | 0.8677 | 0.0034 | 0.8680 |
| Logistic Regression | 0.8590 | 0.0031 | 0.8599 |

Наивный Байес обходит бустинги без настройки — прямое следствие независимости признаков из EDA: предпосылка метода
«признаки независимы при известном классе» здесь близка к реальности. Это наблюдение в итоге и определило решение
(раздел 6).

### 4. Абляция: вклад каждого блока признаков

Все наборы — на одних и тех же фолдах, LightGBM с одинаковыми параметрами, ранняя остановка внутри фолда.

| Набор признаков | Признаков | CV ROC-AUC | std | Прирост |
|---|---|---|---|---|
| 1. сырые признаки | 200 | 0.8965 | 0.0030 | — |
| 2. + частоты по всему тесту | 400 | 0.9040 | 0.0023 | +0.0075 |
| 3. + частоты по настоящему тесту | 400 | 0.9043 | 0.0031 | +0.0003 |
| **4. + is_unique, значение × частота** | **800** | **0.9109** | **0.0023** | **+0.0066** |
| 5. + строковые статистики | 808 | 0.9106 | 0.0021 | −0.0003 |
| 6. + ранги, квадраты, произведения | 1028 | 0.9104 | 0.0021 | −0.0003 |

Выводы:

* Частоты значений дают крупнейший прирост (+0.0078 от сырых признаков к набору 3).
* `is_unique` и произведение значения на частоту — второй по величине вклад (+0.0066).
* Строковые статистики, ранги, квадраты и произведения не дают ничего. Ранг — монотонное преобразование признака,
  дереву он не нужен, а лишние колонки замедляют обучение. Больше признаков ≠ лучше: набор из 1028 колонок
  хуже набора из 800.
* Разделение теста на настоящие и синтетические строки на кросс-валидации выглядит незначимым (+0.0003 при std 0.003).
  Его настоящий эффект виден только в следующем разделе.

Итоговый набор: **№4, 800 признаков** (блоки `raw`, `cnt`, `uniq`, `xcnt`).

### 5. Adversarial validation: различимы ли train и тест

Классификатор учится отличать train от настоящих строк теста. Если это удаётся — распределения разошлись.

| Набор признаков | Adversarial ROC-AUC |
|---|---|
| сырые | 0.5011 |
| сырые + частоты по всему тесту | **1.0000** |
| сырые + частоты по настоящему тесту | 0.5038 |
| итоговый набор | 0.4987 |

Это главный аргумент в пользу того, чтобы считать частоты только по настоящим строкам. На сырых признаках train
и тест неразличимы. Но с частотами по всему тесту классификатор отделяет их **идеально**, и главные признаки —
частотные: синтетические копии завышают частоты значений настоящих строк, и модель учится на распределении,
которого в реальном тесте нет.

На кросс-валидации этот дефект не проявляется совсем: разница между наборами 2 и 3 составляет всего +0.0003.
Отложенная выборка тоже его не ловит, потому что взята из train. Единственный способ его увидеть до отправки —
такая проверка.

### 6. Модели «по одной переменной»

Если признаки независимы при известном классе, общий логит — сумма логитов по отдельным переменным:

```
log P(y=1|x)/P(y=0|x) = Σ log P(y=1|xⱼ)/P(y=0|xⱼ) − 199·log P(y=1)/P(y=0)
```

`GaussianNB` оценивает каждое слагаемое нормальным распределением. Здесь вместо этого — для каждой из 200 переменных
своя маленькая LightGBM (4 листа, ранняя остановка) на паре «значение и его частота», логиты складываются.

| Модель | CV ROC-AUC | std |
|---|---|---|
| Naive Bayes (Gaussian, сырые) | 0.8882 | 0.0021 |
| По переменным: только значение | 0.8862 | 0.0012 |
| **По переменным: значение + частота** | **0.9115** | **0.0020** |
| LightGBM на тех же 400 колонках (набор 3) | 0.9043 | 0.0031 |
| LightGBM на итоговом наборе (800) | 0.9109 | 0.0023 |

Схема обходит LightGBM на тех же данных (0.9115 против 0.9043): она жёстко запрещает взаимодействия между
переменными, которых в данных и нет, и потому не тратит данные на поиск несуществующих зависимостей.
Частоты добавляют в этой схеме +0.0253 — кратно больше, чем в бустингах.

### 7. Подбор гиперпараметров

Случайный поиск на итоговом наборе, те же фолды, ранняя остановка.

| Модель | CV ROC-AUC | std | holdout |
|---|---|---|---|
| LightGBM | 0.9121 | 0.0023 | 0.9140 |
| XGBoost | 0.9126 | 0.0023 | 0.9151 |
| CatBoost | 0.9125 | 0.0024 | 0.9142 |
| LightGBM с параметрами абляции | 0.9109 | — | — |

Прирост от подбора 0.0012–0.0017 при std по фолдам 0.0023, то есть **в пределах разброса**: параметры абляции уже были
близки к оптимуму. Три бустинга после подбора неразличимы между собой — все упираются в одну и ту же структуру данных.
Лучшие параметры при этом очень консервативные (LightGBM: `num_leaves=3`, `colsample_bytree=0.3`), что согласуется
с отсутствием взаимодействий между признаками.

### 8. Ансамбль

Базовые модели: логистическая регрессия и наивный Байес (сырые признаки), модель «по переменным», три настроенных
бустинга. Предсказания переводятся в ранги; веса и мета-модель подбираются только на OOF train-части, сравниваются
на отложенной выборке.

| Метод | Holdout ROC-AUC | Разница с лучшей одиночной |
|---|---|---|
| **одиночная: по переменным** | **0.9218** | 0.0000 |
| взвешенное усреднение (веса по OOF) | 0.9205 | −0.0012 |
| стекинг (LogReg на OOF) | 0.9202 | −0.0016 |
| одиночная: XGBoost | 0.9151 | −0.0066 |
| одиночная: CatBoost | 0.9142 | −0.0075 |
| одиночная: LightGBM | 0.9140 | −0.0078 |
| одиночная: Naive Bayes | 0.8882 | −0.0336 |
| одиночная: Logistic Regression | 0.8599 | −0.0619 |

Веса усреднения: по переменным 0.447, XGBoost 0.264, CatBoost 0.238, LightGBM 0.018, Naive Bayes 0.017,
Logistic Regression 0.016.

**Ансамбль проиграл лучшей одиночной модели.** Две причины. Первая: у модели «по переменным» предсказание для
отложенной выборки — среднее пяти моделей фолдов, каждая из которых складывает 200 шумных слагаемых; усреднение
по фолдам сильно снижает шум, поэтому OOF (предсказание одной модели) её недооценивает, а вместе с ним занижен
и подобранный по OOF вес. Вторая: три бустинга сильно скоррелированы между собой (ранговая корреляция 0.985–0.989)
и добавляют мало нового.

Итоговым методом выбрана одиночная модель «по переменным», и лидерборд это подтвердил: 0.92082 против 0.92002
у усреднения.

## Что сработало и что нет

**Сработало:**

* Частотные признаки — главный источник качества (+0.0078), и считать их нужно только по train и настоящим строкам теста.
* Разделение теста на настоящие и синтетические строки. На CV эффект выглядит незначимым (+0.0003), но adversarial
  validation показывает, что именно он убирает сдвиг распределений (1.0000 → 0.4987).
* Модель «по переменным», построенная на наблюдении из EDA о независимости признаков. Обошла все три настроенных
  бустинга и стала итоговым решением.

**Не сработало:**

* Ранги, квадраты, произведения признаков и строковые статистики: −0.0003 каждое, то есть ничего.
* Раздувание набора признаков: 1028 колонок дают 0.9104 против 0.9109 у 800.
* Подбор гиперпараметров: прирост в пределах стандартного отклонения по фолдам.
* Ансамбль: усреднение и стекинг оба ниже лучшей одиночной модели.

## Воспроизведение

### 1. Окружение

```bash
conda create -n ml_project python=3.11 -y
conda activate ml_project
pip install -r requirements.txt
```

Версии, на которых получен результат: numpy 2.4.6, pandas 3.0.5, scikit-learn 1.9.0, scipy 1.17.1,
lightgbm 4.7.0, xgboost 3.2.0, catboost 1.2.10.

### 2. Данные

```bash
kaggle competitions download -c santander-customer-transaction-prediction -p data/
unzip -d data/ data/santander-customer-transaction-prediction.zip
```

Нужны `train.csv`, `test.csv`, `sample_submission.csv`. Путь к ним задаётся переменной `DATA_DIR`
во второй ячейке ноутбука.

### 3. Запуск

Открыть `notebooks/santander_solution.ipynb` и выполнить все ячейки (Kernel → Restart & Run All).

Полный прогон занимает несколько часов. Для быстрой проверки работоспособности в той же ячейке есть флаг
`FAST_DEBUG = True` — прогон на подвыборке с минимумом итераций.

Тяжёлые этапы кэшируются в папку `cache/` (`joblib`): при повторном запуске они загружаются с диска, а не считаются
заново. Если меняете код этапа — удалите соответствующий файл из `cache/`.

Результаты сохраняются в `submission/submission.csv` (а также `submission_blend.csv` и `submission_per_var.csv`
для сравнения) и `results.json` — все числа этого README берутся оттуда.
